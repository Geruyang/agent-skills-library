# 评估、部署与交付

## 从承诺反推测试

| 承诺 | 有效证据 | 不能替代的证据 |
|---|---|---|
| 工具契约正确 | fixture 输入、真实实现输出、schema/错误断言 | tools/list |
| 权限隔离 | 越权对象/路径/租户被执行端拒绝 | 提示词说不要越权 |
| 可恢复 | 在关键窗口杀进程、重启、对账，副作用数量正确 | 保存消息 JSON |
| 取消有效 | 请求停止、运行终止、资源回收分别观测 | UI 按钮点击 |
| 业务正确 | 可复现样本、参考答案或业务谓词、错误分析 | 模型自评或单个展示案例 |
| 客户端兼容 | 目标客户端加载正文、工具调用、媒体/UI 逐项观察 | 文件复制完成 |

确定性 fake model 可验证循环、序列化、权限和协议；真实模型用于任务完成率、工具路由和输出质量。不要把假模型路径通过写成真实模型质量验证。

## 最小故障集合

根据实现范围选适用项：工具参数错误；工具超时；返回过大；模型 429/断流；在副作用后写 receipt 前进程丢失；重复用户输入/队列投递；审批后参数改变；审批时刷新；取消时子工具仍运行；检查点版本不兼容；另一个租户读取产物；并发两个 run 写同一 thread。

至少一条正常用例和一条会改变选型结论的失败用例。不要为了形式添加与实现同构的测试；记录输入、版本、环境、预期、实际、证据位置和未覆盖部分。

## 质量评估

按业务成功、约束遵守、工具正确性、成本、p50/p95 延迟、恢复/人工接管率观察。用固定样本与 held-out 分离调参和验收，重复随机运行报告波动。LLM judge 使用清楚 rubric、校准人工样本、盲测候选顺序和长度偏差；关键事实和权限用确定性检查。

对照实验一次改变一个因素：模型、工具描述、检索、压缩、拓扑。维护失败 taxonomy 和版本记录；优化平均分不应掩盖不可接受的越权或重复交易。自改进 agent 不得同时修改被考核任务和评分器。

## 部署责任

开发原型可使用本地文件/SQLite；多进程服务需要明确事件存储、事务/锁、队列租约、任务去重、工作区生命周期、凭证来源和日志/产物保留。多副本不是简单增加容器：验证同一任务不会被两个 worker 同时执行。

固定 SDK、模型标识、工具定义、skill 内容与 schema 版本。更新时核对源码 API、许可证、lockfile 和迁移；保存回滚点，注意旧 worker 是否读得懂新 checkpoint。可观测性串联 request/thread/run/call/operation key，记录状态与耗时，不记录密钥或完整隐私内容。

环境清理采用明确所有权和 TTL；后台任务到期停止，产物按保留策略持久化。Windows 测试重点包括长路径、symlink/junction 权限、PowerShell/命令参数、子进程退出和路径空格；Linux/macOS 仍需平台验证。

## 历史证据使用边界

本技能索引记录本会话下载版本和已有报告事实，并未重跑 35 个工程。历史报告中的 667 技能结构检查、16 MCP 本地握手、20 Claude 连接、TRAE 网关图表预览等属于各自有限测试层。MCP reference 上游 Node 测试曾有 Windows symlink EPERM 失败；保留这项限制，不能概括为全量通过。

新的项目仍必须按其版本和部署环境测试。仅有 source inspection 的功能标“源码支持、运行未验证”；仅有配置定义的 SaaS 标“需账号/供应商前提”。
