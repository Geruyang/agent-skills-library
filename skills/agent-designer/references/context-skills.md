# 上下文、记忆与技能组合

本次 667 个导出技能全部进入 [skill-index.json](skill-index.json)，由六个下载仓库贡献：OpenAI plugins 532、OpenAI skills 44、Anthropic official plugins 32、Context Engineering 24、Anthropic skills 20、Superpowers 15。另有本次编写的 agent-foundation 技能，单列来源，不改写 667 的计数。

全量覆盖的含义是每个导出条目都有来源、正文 hash、目录、类别和使用边界；不意味着每个技能的业务流程都已运行，更不意味着应把所有指令合并进当前会话。

## 从资料到上下文的选择流水线

1. 发现阶段仅加载 name、description、来源、适用范围。按目标检索，不按“与 agent 有关”就全选。
2. 入选后读取 SKILL.md，判断是通用方法、仓库专用开发规则还是特定 SaaS/业务技能；检查工具、资源和授权前提。
3. 只读取当前阶段的引用，保留源文件路径与版本。大型结果写入项目产物存储，给模型摘要、检索入口和必要片段。
4. 对压缩和检索做 end-to-end task 测量：重读成本、遗漏率、最终成功率，而非仅看单次 token 下降。

跨客户端迁移保留原始 skill 与适配副本的关系。`$skill`、专有工具名、hooks、环境变量、插件依赖不保证通用；把必要行为映射成当前可用能力，无法映射的明确标缺失。不要通过复制个人配置“补齐”下载包。

| 来源族 | 吸收的设计知识 | 不继承的假设 |

索引的分类由内容关键词生成，便于检索，可能多标签且需人工判断。query 脚本排序不是语义评估器，不用于自动执行。

## 记忆层选择

- **会话历史**：模型交互证据，保留 tool call/result 的对应。
- **任务工作区**：当前计划、文件、状态、产物；可清理和重建。
- **长期记忆**：跨会话仍有价值的事实/偏好；需要主体、来源、有效期、置信/确认状态、访问控制和删除。
- **检索索引**：派生加速层，更新和删除须跟随源；不能当权威业务数据库。

向量检索适合语义近邻，结构化库适合精确主体与时间，图适合关系查询；可以混合，但先用具体问答证明增加复杂度的价值。BDI/RDF 只在业务确需显式信念/目标/意图语义时引入。

## 压缩与优化的顺序

先减少无关输入与重复 schema，再做检索和大结果外置，最后评估摘要/压缩。固定前缀有利于缓存但不能缓存用户权限；不要为 cache hit 保留过期授权或不相关资料。自动摘要保留最近用户约束、未决问题、动作 receipt 和下一步，不以“摘要写了”代替源文件确认。

`latent-briefing`、可写上下文和自改进循环属于高级候选方法：模型/推理服务若不公开 KV cache 或相应 API，不能承诺跨 agent latent memory。自改进必须锁定评估数据/评分逻辑，候选变化独立评估且可回滚；不自动修改本技能或用户全局规则。
